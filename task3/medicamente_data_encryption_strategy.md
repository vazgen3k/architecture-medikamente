#  Оценка Data Encryption at Rest and In Transit


## 1. Классификация данных для защиты

| Данные | В чём необходимость защиты | Инструменты защиты |
|---|---|---|
| ФИО пациента | Персональные данные. Позволяют идентифицировать пациента. Утечка приведёт к нарушению конфиденциальности. | Шифрование at-rest, TLS при передаче, маскирование в интерфейсах и логах, RBAC/ABAC, аудит доступа. |
| Дата рождения пациента | Персональные данные. В сочетании с ФИО повышает риск точной идентификации. | Шифрование at-rest, TLS, ограничение доступа, маскирование в аналитике. |
| Телефон и email пациента | Контактные ПДн. Могут использоваться для спама, мошенничества и социальной инженерии. | Шифрование, TLS, маскирование, запрет логирования в открытом виде, DLP-контроль выгрузок. |
| Адрес регистрации/проживания | Чувствительные ПДн. Утечка может привести к физическим и репутационным рискам для пациента. | Шифрование, строгий RBAC/ABAC, маскирование, минимизация сбора, аудит. |
| Место работы/учёбы | Избыточные ПДн для части процессов. Повышает риск профилирования пациента. | Минимизация сбора, шифрование, ограничение доступа, удаление при отсутствии необходимости. |
| Данные договора | Содержат ПДн, условия оказания услуг, подписи и реквизиты. | Шифрование файлов/объектов, контроль доступа, DLP, аудит скачивания и просмотра. |
| Медицинская карта | Медицинская тайна. Содержит сведения о факте обращения, состоянии здоровья, назначениях и лечении. | Шифрование на уровне БД и файлов, ABAC, обязательный аудит, KMS/Vault, запрет логирования значений, SIEM-алерты. |
| Диагноз | Наиболее чувствительная медицинская информация. Утечка несёт высокий репутационный и правовой риск. | Шифрование, доступ только врачу/пациенту-владельцу, ABAC, маскирование, аудит каждого доступа, запрет передачи в аналитику без обезличивания. |
| Назначения врача и план лечения | Медицинская тайна. Может раскрывать состояние здоровья пациента. | Шифрование, ABAC, аудит, контроль целостности, доступ только уполномоченным врачам и пациенту. |
| Результаты анализов | Медицинская тайна. Используются во внутренней системе и передаются лабораторией. | TLS/mTLS при обмене, шифрование at-rest, псевдонимизация идентификатора заказа, аудит обмена, проверка целостности. |
| Расписание и запись к врачу | Может раскрывать факт обращения за медицинской помощью. | TLS, RBAC, минимизация данных в уведомлениях, аудит изменений, проверка ownership для пациента. |
| Платёжные данные | Содержат сведения об оплатах, услугах, суммах и связи с пациентом. | Шифрование, TLS, RBAC для кассира/бухгалтерии, аудит операций, защита интеграции с ККМ и 1С. |
| Данные сотрудников | Кадровые и зарплатные данные. Конфиденциальны внутри компании. | Шифрование, RBAC для бухгалтерии/HR, аудит доступа, ограничение выгрузок. |
| Данные ТМЦ и закупок | Коммерчески значимая информация. Может раскрывать внутренние операции компании. | RBAC, аудит изменений, резервное копирование, защита интеграции 1С. |
| Логи аудита | Содержат события доступа к чувствительным данным. Не должны быть изменены злоумышленником. | WORM/append-only хранение, контроль целостности, ограничение доступа, отправка в SIEM, шифрование. |
| Резервные копии | Могут содержать полный набор ПДн, медицинских и платёжных данных. | Обязательное шифрование, KMS, контроль доступа, изолированное хранение, тесты восстановления. |
| Аналитические датасеты | Могут содержать производные данные о пациентах и услугах. | Обезличивание, псевдонимизация, агрегация, доступ только к витринам, Data Catalog, Data Lineage. |
| ML/AI-датасеты | Риск попадания чувствительных данных в модели и последующего восстановления информации. | Использование только обезличенных/псевдонимизированных данных, отдельное разрешение на использование, контроль датасетов, аудит. |

## 2. Классификация по состоянию данных

| Состояние данных | Где встречается в системе | Основные риски | Меры защиты |
|---|---|---|---|
| Data at Rest | PostgreSQL, ClickHouse, файловое хранилище, S3/MinIO, 1С, резервные копии, архивы | Кража диска, компрометация БД, доступ к файлам, утечка бэкапов | Шифрование дисков/томов, TDE или шифрование на уровне приложения, шифрование объектного хранилища, KMS/Vault, RBAC, аудит. |
| Data in Transit | HTTPS-запросы, API Gateway, сервис-сервисное взаимодействие, лаборатория, ККМ, 1С, Kafka | Перехват трафика, MITM-атаки, подмена данных | TLS 1.2+/1.3, mTLS для сервисов и лаборатории, VPN для внешних интеграций, подпись сообщений, защищённые протоколы. |
| Data in Use | Интерфейсы, backend, ETL/ELT, BI, ML/AI | Чрезмерное отображение данных, попадание ПДн в логи, утечка через отчёты или модели | Маскирование в UI, фильтрация полей по RBAC/ABAC, запрет логирования чувствительных значений, обезличивание перед аналитикой, контроль выгрузок. |

## 3. Классификация по чувствительности и риску

| Класс данных | Примеры | Уровень риска | Требуемая защита |
|---|---|---|---|
| Public | Публичная информация о компании, расписание работы филиалов | Низкий | Контроль целостности, базовый доступ. |
| Internal | Внутренние документы, справочники, данные ТМЦ | Средний | RBAC, аудит изменений, резервное копирование. |
| PII | ФИО, дата рождения, телефон, email, адрес | Высокий | Шифрование, TLS, маскирование, RBAC/ABAC, аудит. |
| Sensitive PII | Адрес, место работы, расширенная анкета, сведения о здоровье | Высокий/критичный | Шифрование, минимизация, ABAC, аудит, DLP. |
| Medical Secret | Диагноз, медицинская карта, результаты анализов, факт обращения | Критичный | Шифрование, строгий ABAC, аудит каждого доступа, SIEM-алерты, запрет использования в аналитике без обезличивания. |
| Payment | Платежи, возвраты, связь оплаты с пациентом и услугой | Высокий | Шифрование, TLS, RBAC, аудит, контроль интеграции с ККМ/1С. |
| Credentials/Secrets | Пароли, токены, API-ключи, ключи шифрования | Критичный | Vault/KMS, ротация секретов, запрет хранения в коде, аудит использования. |
| Audit/Security Logs | События доступа, отказы, выгрузки, изменения | Высокий | Защита от изменения, шифрование, SIEM, ограничение доступа. |
| Anonymized Analytics | Обезличенные агрегаты, витрины BI | Низкий/средний | Контроль повторной идентификации, Data Catalog, ограничение выгрузок. |
| Pseudonymized Analytics | Данные с заменённым идентификатором пациента | Средний/высокий | Раздельное хранение ключа сопоставления, RBAC, аудит, запрет обратной идентификации без основания. |

## 4. Базовые инструменты защиты, которые нужно реализовать

| Инструмент / мера | Назначение | Где применяется |
|---|---|---|
| TLS 1.2+/1.3 | Шифрование данных при передаче | Все внешние и внутренние HTTP/API-соединения. |
| mTLS | Взаимная аутентификация сервисов | Backend-сервисы, интеграция с лабораторией, критичные внутренние API. |
| VPN-туннель | Защита интеграции с внешней лабораторией или удалёнными филиалами | Лаборатория, филиалы, админ-доступ. |
| KMS / HashiCorp Vault | Управление ключами шифрования, секретами, токенами и сертификатами | БД, сервисы, бэкапы, API-интеграции. |
| Шифрование дисков/томов | Защита данных при физическом доступе к серверу или диску | Серверы БД, файловое/объектное хранилище, backup-storage. |
| Шифрование колонок | Дополнительная защита наиболее чувствительных полей | Диагноз, результаты анализов, адрес, телефон, паспортные/договорные данные. |
| RBAC | Доступ по ролям | Пациент, врач, ресепшен, кассир, бухгалтер, аналитик, администратор. |
| ABAC | Доступ по атрибутам | Лечащий врач, филиал, принадлежность данных пациенту, тип документа, цель обработки. |
| API Gateway | Контроль входящих запросов | Client App, Employee App, лаборатория, партнёрские API. |
| Audit Log Service | Централизованное логирование действий | Доступ к ПДн, медицинским картам, платежам, согласиям, выгрузкам. |
| SIEM | Анализ событий безопасности и алертинг | Аномальный доступ, массовые выгрузки, отказы доступа, подозрительные действия. |
| DLP | Предотвращение утечек | Почта, рабочие станции, выгрузки файлов, отчёты. |
| Data Catalog / OpenMetadata / Apache Atlas | Каталог данных, теги, владельцы, lineage | Операционные системы, DWH, BI, ML/AI. |
| Anonymization/Pseudonymization Service | Подготовка данных для аналитики | Airflow/ETL, DWH, BI, ML/AI. |
| Backup Encryption | Защита резервных копий | Все резервные копии БД, файлов и конфигураций. |

## 5. Автоматизированный контроль за данными


| Средство контроля | Что контролирует | Как применяется |
|---|---|---|
| Data Catalog / OpenMetadata / Apache Atlas | Наличие тегов, владельцев, lineage | Все таблицы, поля, файлы и витрины должны быть зарегистрированы и классифицированы. |
| CI/CD проверки API-контрактов | Попадание чувствительных полей в API | Проверка, что поля с тегами PII/MEDICAL_SECRET не отдаются неподходящим ролям. |
| Static Application Security Testing | Ошибки в коде, небезопасная работа с секретами | Проверка кода на хранение ключей, токенов и чувствительных данных. |
| Secret scanning | Секреты в репозиториях | Блокировка коммита/релиза при обнаружении токенов, паролей, приватных ключей. |
| Dynamic/API Security Testing | Ошибки авторизации и доступа | Проверка, что пациент не может получить данные другого пациента. |
| Database Activity Monitoring | Запросы к БД и массовые выгрузки | Контроль чтения чувствительных таблиц и подозрительных запросов. |
| SIEM-корреляция | Аномалии поведения | Алерты на доступ вне рабочего времени, массовое скачивание, частые отказы доступа. |
| DLP | Вынос данных за периметр | Контроль отправки Excel/PDF/JPG, выгрузок BI и почтовых сообщений. |
| Airflow data quality checks | Нарушение правил аналитики | Проверка, что в DWH/BI не попали открытые ПДн и медицинская тайна. |
| KMS/Vault audit | Использование ключей и секретов | Логирование операций чтения секретов, ротации ключей и выдачи сертификатов. |

## 6. Реестр программных и аппаратных средств защиты данных

| Средство | Тип | Для чего используется | Какие данные защищает |
|---|---|---|---|
| Keycloak / IAM / SSO | Программное средство | Аутентификация, SSO, MFA, управление пользователями и ролями | Все данные через контроль доступа пользователей. |
| OPA / Policy Engine | Программное средство | RBAC/ABAC, проверка доступа по ролям, атрибутам и тегам | ПДн, медицинские, платёжные, аналитические данные. |
| API Gateway | Программное средство | Контроль API, TLS, rate limiting, маршрутизация, аудит | Все данные, проходящие через API. |
| HashiCorp Vault / KMS | Программное средство | Хранение ключей, секретов, сертификатов, ротация | Ключи шифрования, токены, пароли, сертификаты. |
| PostgreSQL encryption / disk encryption | Программное/инфраструктурное средство | Шифрование БД и дисков | CRM DB, Medical DB, Consent DB, Billing DB. |
| Object Storage encryption | Программное средство | Шифрование файлов и документов | PDF, JPG, договоры, медицинские документы. |
| Kafka ACL + TLS | Программное средство | Защита шины данных | События, CDC, сырые данные для аналитики. |
| Airflow | Программное средство | Контролируемая загрузка и обработка данных | ETL/ELT потоки, обезличивание, lineage. |
| Apache Atlas | Программное средство | Каталог данных, классификация, теги, lineage | Все классы данных, особенно ПДн и медицинская тайна. |
| ClickHouse / DWH | Программное средство | Хранение аналитических витрин | Обезличенные и псевдонимизированные данные. |
| ELK  | Программное средство | Централизованное логирование | Логи приложений и аудита без чувствительных значений. |
| SIEM | Программное средство | Корреляция событий и алерты | События доступа, выгрузок, отказов и аномалий. |
| DLP | Программное средство | Предотвращение утечек через почту, файлы и рабочие станции | Excel, PDF, JPG, отчёты, выгрузки. |
| Backup system | Программное/аппаратное средство | Резервное копирование и восстановление | Все БД, файлы, конфигурации, журналы. |
| HSM или аппаратный KMS | Аппаратное средство | Аппаратная защита ключей шифрования при высоких требованиях | Мастер-ключи, ключи шифрования БД и бэкапов. |
| Firewall / NGFW | Аппаратное/программное средство | Сегментация сети и фильтрация трафика | Сетевой доступ к сервисам, БД, 1С, ККМ, лаборатории. |
| VPN Gateway | Аппаратное/программное средство | Защищённый канал для лаборатории и филиалов | Данные анализов, административный доступ, межфилиальный обмен. |
